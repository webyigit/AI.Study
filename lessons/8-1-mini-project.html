Module 8-1

나만의 미니 프로젝트 기획해보기

1-1부터 7-5까지 배운 조각들을 흩어진 지식으로 남겨두지 않고, 작지만 끝까지 완성되는 결과물 하나로 묶어보는 방법입니다.

본문 한눈에 정리 참고문헌

지금까지의 모듈은 대부분 "개념을 이해하고, 작은 예시로 연습하는" 구조였습니다. 이번 모듈은 다릅니다. 배운 것을 내 손으로 처음부터 끝까지 완성해보는 단계입니다. 거창한 서비스를 만들 필요는 없습니다. 오히려 작을수록, 빨리 끝낼수록 좋습니다.

1) 왜 지금, 미니 프로젝트인가

커리큘럼을 완주했다고 해서 그 지식이 저절로 몸에 남지는 않습니다. 강의나 아티클로 배운 개념은 시간이 지나면 빠르게 휘발되는데, 이를 막는 가장 확실한 방법은 실제로 써서 문제를 해결해보는 것입니다. 연구들도 일관되게 같은 결론을 가리킵니다 — 수동적으로 읽거나 듣기만 한 지식보다, 직접 만들면서 얻은 지식이 훨씬 오래 남고 실전 상황에 더 잘 옮겨간다는 것입니다.

또한 미니 프로젝트는 여러 모듈에서 따로 배운 조각들을 한 번에 엮어보는 자리이기도 합니다. 예를 들어 3-6의 실전 프롬프트, 4-4의 회의록 자동 요약, 6-2의 노코드 자동화를 따로따로 "이해는 했지만" 실제로 연결해본 적은 없을 수 있습니다. 미니 프로젝트는 이 연결 지점을 직접 확인하는 자리입니다.

2) 좋은 미니 프로젝트의 세 가지 조건

사이드 프로젝트가 흐지부지되는 가장 흔한 이유는 재능 부족이 아니라, 완성 기준이 없고 범위가 계속 늘어나기 때문입니다. 그래서 아이디어를 고를 때부터 다음 세 가지를 기준으로 삼는 것이 좋습니다.

작을 것 — 집중해서 매달렸을 때 1~2주 안에 첫 버전이 나오지 않는다면 범위가 너무 큽니다. "완벽한 도구"가 아니라 "한 가지 문제를 겨우 풀어내는 도구"를 목표로 삼으세요.
실제 문제일 것 — 가상의 문제보다, 이번 주에 내가 실제로 겪은 귀찮음(반복되는 회의록 정리, 매번 새로 짜는 리서치 프롬프트 등)에서 출발한 프로젝트가 끝까지 갈 확률이 훨씬 높습니다.
완료 지점이 있을 것 — "언젠가 더 다듬어야지"가 아니라, "이 조건을 만족하면 끝"이라는 구체적인 완료 기준을 프로젝트를 시작하기 전에 먼저 정해두세요.

3) 시작하기 좋은 예시 프로젝트 4가지

UX·프로덕트 기획자의 실무와 맞닿아 있으면서, 이 커리큘럼에서 배운 여러 모듈을 자연스럽게 엮을 수 있는 아이디어 네 가지를 소개합니다. 그대로 따라 해도 되고, 내 업무 상황에 맞게 변형해도 좋습니다.

프로젝트무엇을 만드는가주로 엮이는 모듈
AI 회의록 정리 워크플로우회의 녹음을 전사 → 요약 → 결정사항/액션아이템 정리까지 자동으로 흘려보내는 파이프라인4-4, 6-2
개인 AI 리서치 어시스턴트관심 주제를 던지면 정해진 형식(배경·핵심 발견·출처)으로 정리해주는 나만의 리서치 프롬프트 세트2-5, 3-6
사용자 인터뷰 인사이트 정리 도구인터뷰 녹취를 업로드하면 주제별로 태깅하고 페르소나 초안까지 뽑아주는 워크플로우4-2, 6-2
업무용 프롬프트 라이브러리기획서·보고서 등 반복 작성하는 문서용 프롬프트를 모아 버전 관리하는 나만의 도구함3-1~3-5, 4-1
예시로 살펴보는 "AI 회의록 정리 워크플로우" — 회의 녹음 파일을 클로바노트 같은 전사 도구에 넣고, 나온 텍스트를 4-4에서 연습한 요약 프롬프트에 붙여 결정사항·액션아이템을 뽑습니다. 여기까지는 수동으로도 충분히 가능한 범위입니다. 시간이 남으면 6-2에서 다룬 노코드 자동화 도구로 "녹음 파일 업로드 → 전사 → 요약 → 슬랙 전송"까지 자동으로 이어지게 만들면 완성도가 한 단계 올라갑니다. 중요한 것은 처음부터 자동화까지 욕심내지 않고, 수동 버전이 먼저 실제로 돌아가는 것을 확인한 다음 자동화를 얹는 순서입니다.

4) 프로젝트 스코핑 체크리스트

아이디어를 정했다면, 시작하기 전에 아래 네 가지 질문에 한두 문장씩 답을 적어보세요. 이 표 하나만 채워도 "무엇을 만들지 몰라서" 멈추는 일은 크게 줄어듭니다.

항목스스로에게 던질 질문
목표이 프로젝트가 풀어주는 나의 구체적인 불편함은 무엇인가? (예: "매주 회의록 정리에 30분씩 쓰는 게 아깝다")
범위첫 버전에 반드시 있어야 하는 기능은 무엇이고, 나중으로 미뤄도 되는 기능은 무엇인가?
사용할 도구어떤 모듈에서 배운 방법(프롬프트 구조, 노코드 자동화, RAG 등)을 조합할 것인가?
완료 기준어떤 조건을 만족하면 "완성"이라고 부를 것인가? (예: "실제 회의 2건을 이 워크플로우로 정리해봤다")

완료 기준은 특히 중요합니다. 기준이 없으면 "조금만 더 다듬으면 완벽해질 것 같아서" 계속 미루게 되고, 결국 아무것도 공개되지 않은 채 흐지부지되기 쉽습니다. 목표는 완벽한 프로덕트가 아니라, 내가 실제로 한 번 이상 써본 작은 결과물입니다.

정리하면

단계핵심
왜배운 지식은 직접 만들어봐야 오래 남는다
조건작을 것, 실제 문제일 것, 완료 지점이 있을 것
아이디어회의록 자동화·리서치 어시스턴트·인터뷰 정리 도구·프롬프트 라이브러리 등
체크리스트목표 · 범위 · 사용할 도구 · 완료 기준을 먼저 글로 적는다
이해 확인 — 지금 바로 체크리스트 표의 네 칸(목표·범위·사용할 도구·완료 기준)을 실제 메모 앱에 채워보세요. 완벽하지 않아도 됩니다. 다음 모듈(8-2. 꾸준히 학습을 이어가는 방법)로 넘어가기 전, 이 커리큘럼에서 가장 실전에 가까운 한 걸음입니다.
