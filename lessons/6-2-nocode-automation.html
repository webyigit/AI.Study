Module 6-2

노코드/로코드로 AI 자동화 직접 만들어보기

코드를 한 줄도 쓰지 않고, "이런 일이 생기면 AI가 이렇게 처리한다"는 자동화를 직접 설계해볼 수 있는 도구와 개념을 이해합니다.

본문 한눈에 정리 용어 상세 참고문헌

6-1에서 "AI API 호출"이 요청과 응답을 주고받는 일이라는 걸 봤습니다. 문제는 그 요청을 "누가, 언제" 보내느냐입니다. 사람이 매번 버튼을 눌러 보내는 대신, 특정 상황이 벌어지면 자동으로 그 요청이 나가도록 만드는 것이 이번 모듈의 주제, 자동화입니다.

1) 노코드/로코드란 무엇인가

노코드(No-Code)는 말 그대로 "코드를 쓰지 않는다"는 뜻입니다. 화면에서 상자와 화살표를 마우스로 끌어다 연결하면, 그 뒤에서 실제 코드가 자동으로 만들어져 실행됩니다. 레고 블록을 조립하듯, "이 상자가 끝나면 저 상자를 실행한다"는 흐름을 시각적으로 그리는 방식입니다.

로코드(Low-Code)는 기본은 노코드처럼 마우스로 조립하되, 세밀한 조건이 필요할 때는 아주 짧은 코드 몇 줄을 끼워 넣을 수 있게 열어둔 절충형입니다. 이 모듈에서는 굳이 둘을 엄격히 구분하지 않고, "코드를 직접 짜지 않고도 시스템을 연결할 수 있는 도구들"을 통칭해서 다룹니다.

2) 자동화의 기본 구조 — 트리거와 액션

모든 자동화는 딱 두 부분으로 이루어져 있습니다. "무엇이 일어나면(트리거)" + "무엇을 할 것인가(액션)"입니다. 이 둘 사이에 AI 단계를 하나 끼워 넣으면, 그게 바로 "AI 자동화"입니다.

예시 — "새 문의가 오면(트리거) → AI가 문의 내용을 요약하고 카테고리를 분류해서(AI 단계) → 담당 팀 슬랙 채널에 올린다(액션)". 이 세 단계를 마우스로 순서대로 연결하기만 하면, 사람이 매번 확인해서 요약할 필요 없이 자동으로 처리됩니다.

여기서 "AI 단계"가 정확히 하는 일은 6-1에서 본 API 호출과 같습니다. 노코드 도구가 사용자 대신 "문의 내용을 요약해줘"라는 요청을 AI API로 보내고, 돌아온 응답(요약문)을 다음 단계(슬랙 전송)로 그대로 넘겨주는 것입니다. 즉 노코드 자동화 도구는 여러 개의 API 호출을 순서대로 자동 연결해주는 중간 다리 역할을 합니다.

3) 대표적인 도구 카테고리

구체적인 제품 이름과 기능은 계속 바뀌기 때문에, 여기서는 "어떤 역할을 하는 카테고리인지"만 잡아둡니다.

카테고리대표적으로 하는 일
범용 워크플로우 자동화여러 앱(메일, 시트, 메신저, DB 등)을 트리거-액션으로 연결. AI 단계도 하나의 블록으로 끼워 넣을 수 있음
챗봇/상담 자동화고객 문의창에 AI 응답을 자동 연결. 특정 조건에서만 사람에게 넘기는 분기 설정 가능
사내 문서/데이터 자동화스프레드시트나 문서 도구 안에서 AI 함수를 호출해 요약·분류·초안 생성
노코드 앱 빌더화면(폼, 대시보드)까지 마우스로 만들고, 그 안에 자동화 로직을 결합

실무에서는 보통 "가장 많이 쓰는 협업 도구(메일, 메신저, 스프레드시트)를 얼마나 폭넓게 지원하는가"와 "AI 단계를 얼마나 쉽게 끼워 넣을 수 있는가"로 도구를 고릅니다. 특정 제품을 배우기보다, 이 카테고리 개념을 알고 있으면 어떤 신제품이 나와도 "아, 이건 그 카테고리구나"라고 빠르게 이해할 수 있습니다.

4) 개념적으로 자동화 하나를 만들어본다면

실제 화면은 도구마다 다르지만, 어떤 도구를 쓰든 설계 순서는 거의 동일합니다.

설계 순서 예시 — "고객 후기가 새로 등록되면, AI가 긍정/부정을 판단해서 부정적인 후기만 담당자에게 알림을 보낸다"

① 트리거 정하기 — "후기 게시판에 새 글이 등록됨"을 감지 지점으로 설정
② AI 단계 연결 — 새로 들어온 후기 텍스트를 AI 블록에 넣고, "이 글이 긍정적인지 부정적인지 판단해줘"라는 지시문(프롬프트)을 미리 써둠
③ 조건 분기 — AI 응답이 "부정적"이면 다음 단계로, "긍정적"이면 흐름을 종료하도록 갈림길 설정
④ 액션 실행 — 조건을 통과한 경우에만 메신저로 알림 전송

여기서 실제로 손으로 타이핑하는 부분은 "②의 프롬프트 문구"와 "③의 조건문" 정도이고, 나머지는 마우스로 상자를 끌어다 연결하는 작업입니다. 한 번 만들어두면 이후로는 사람이 개입하지 않아도 같은 흐름이 반복 실행됩니다. 처음 설계할 때는 복잡해 보여도, "트리거 → (필요하면 AI) → 조건 → 액션"이라는 네 칸짜리 틀 자체는 거의 모든 자동화에 똑같이 적용됩니다.

정리하면

개념한 줄 정의
노코드/로코드코드를 직접 짜지 않고 마우스로 흐름을 조립해 시스템을 연결하는 방식
자동화"트리거(무엇이 일어나면)"와 "액션(무엇을 할 것인가)"을 미리 연결해두는 것
AI 단계자동화 흐름 중간에 AI API 호출을 끼워 넣어 요약·분류·생성 등을 수행하는 블록
조건 분기AI 응답 내용에 따라 흐름을 갈라 필요한 경우에만 다음 액션을 실행

노코드 자동화를 알아둬야 하는 이유는 코딩을 하기 위해서가 아니라, "이 정도는 개발자 없이도 직접 만들 수 있는 일인지, 아니면 별도 개발이 필요한 일인지"를 스스로 판단할 수 있게 되기 위해서입니다. 이 감각이 있으면 기획서를 쓸 때부터 범위를 훨씬 현실적으로 잡을 수 있습니다.

이해 확인 — "새 계약서가 업로드되면 AI가 핵심 조항을 요약해서 담당자 메일로 보낸다"는 자동화를 위 네 칸(트리거/AI/조건/액션)으로 스스로 나눠보세요. 다음 모듈(6-3. 벡터DB와 임베딩, 실습으로 감 잡기)에서는 이 AI 단계 안에서 "회사 내부 문서"를 참고하게 만드는 원리를 다룹니다.

노코드/로코드 (No-Code / Low-Code)

↑ 본문으로

전통적인 프로그래밍 코드를 직접 작성하지 않고, 시각적인 화면에서 블록을 끌어다 연결하는 방식으로 소프트웨어나 자동화 흐름을 만드는 접근법입니다. 노코드는 코딩을 전혀 요구하지 않고, 로코드는 기본은 시각적 조립이되 필요할 때 짧은 코드를 추가할 수 있게 열려 있습니다. 개발자가 아닌 기획자·마케터도 직접 도구를 다룰 수 있게 해주는 것이 핵심 가치입니다.

자동화 (Automation)

↑ 본문으로

특정 조건(트리거)이 충족되면 사람의 개입 없이 미리 정해둔 작업(액션)이 자동으로 실행되도록 만드는 것입니다. "새 문의 등록 → AI 요약 → 슬랙 알림"처럼 여러 단계를 하나의 흐름으로 연결해두면, 이후로는 같은 상황이 반복될 때마다 자동으로 처리됩니다. AI 단계가 포함된 자동화를 흔히 "AI 자동화"라고 부릅니다.
