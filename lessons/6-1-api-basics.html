Module 6-1

API란 무엇이고, AI API는 어떻게 호출되는가

개발자가 "이거 API로 연동하면 돼요"라고 말할 때, 실제로는 무엇을 누구에게 보내고 무엇을 돌려받는다는 뜻인지 레스토랑 비유와 실제 요청·응답 예시로 감을 잡습니다.

본문 한눈에 정리 용어 상세 참고문헌

기획 회의에서 "그건 API로 붙이면 돼요"라는 말을 들어본 적 있을 겁니다. API는 마법 같은 단어가 아니라, 아주 단순한 약속입니다. "이렇게 요청하면, 저렇게 답해주겠다"는 두 시스템 사이의 계약서일 뿐입니다.

1) 레스토랑 비유로 시작하기

식당에서 손님은 주방에 직접 들어가지 않습니다. 대신 점원(서버)에게 "이 메뉴 주세요"라고 말하고, 점원이 주방에 전달하고, 완성된 음식을 다시 손님에게 가져다줍니다. 여기서 손님은 주방이 어떻게 요리하는지 전혀 몰라도 됩니다. 그저 정해진 메뉴판(=API 문서)을 보고 주문하는 방법만 알면 됩니다.

비유 대응 — 손님 = 우리 서비스(요청하는 쪽) / 점원 = API / 주방 = 상대 시스템(실제 일을 처리하는 쪽) / 메뉴판 = API 문서. 손님이 메뉴에 없는 걸 주문할 수 없듯, 우리 서비스도 상대가 "받아주기로 약속한 형식"으로만 요청할 수 있습니다.

즉 API(Application Programming Interface)는 서로 다른 두 프로그램(또는 회사, 서비스)이 "이 형식으로 말 걸면, 이 형식으로 답해줄게"라고 미리 정해둔 소통 창구입니다. 상대방 시스템의 내부 코드를 몰라도, 이 창구를 통해서만 정확한 형식으로 요청하면 원하는 결과를 받을 수 있습니다.

2) 왜 "연동"이라는 말이 나오는가

우리 서비스가 결제 기능을 만든다고 해봅시다. 카드 결제 로직을 처음부터 직접 만들려면 은행, 카드사와 계약하고 보안 인증을 받는 등 몇 달이 걸립니다. 그런데 토스페이먼츠나 아임포트 같은 결제 회사가 이미 그 기능을 API로 열어두었다면, 우리는 "이 형식으로 결제 요청을 보내면 된다"는 문서만 보고 며칠 안에 결제 기능을 가져다 쓸 수 있습니다.

기획 문서에서 "OO API 연동"이라고 쓰는 건 바로 이 뜻입니다. 우리가 그 기능을 직접 만들지 않고, 이미 만들어진 남의 기능을 정해진 방식으로 빌려 쓴다는 것입니다. AI 기능도 마찬가지입니다. ChatGPT나 Claude를 우리 서비스 안에 "탑재"한다는 건, 대부분 그 회사가 제공하는 API를 호출해서 결과를 받아온다는 뜻입니다.

3) 요청(Request)과 응답(Response) — API 대화의 기본 구조

모든 API 호출은 두 문장으로 이루어진 대화입니다. 내가 먼저 요청(Request)을 보내고, 상대가 응답(Response)을 돌려줍니다. 전화 통화처럼 한쪽이 먼저 말을 걸어야 대화가 시작됩니다.

요청에는 보통 세 가지가 담깁니다.

요청 구성요소레스토랑 비유의미
엔드포인트(URL)어느 가게에 전화하는가요청을 보낼 정확한 주소
인증키(API Key)단골 회원증 제시"나는 이 API를 쓸 자격이 있다"는 증명
본문(Body)실제 주문 내용내가 원하는 작업의 구체적인 내용

응답에는 상대가 처리한 결과와, 그 결과가 성공했는지 실패했는지를 알려주는 상태 코드가 함께 담깁니다. 흔히 보는 "200 성공", "404 찾을 수 없음", "401 인증 실패" 같은 숫자가 바로 이 상태 코드입니다.

4) AI API 호출, 실제로 뜯어보기

이제 이 원리를 그대로 AI에 적용해봅니다. 우리 서비스가 "사용자가 입력한 문의 글을 한 줄로 요약해줘"라는 작업을 AI 모델에게 시킨다고 해봅시다. 이때 우리 서비스가 AI 회사 서버로 보내는 요청은 대략 이런 모습입니다. (실제 필드명은 회사마다 조금씩 다르지만 구조는 거의 동일합니다.)

요청(Request) 예시 — 우리 서비스가 AI 서버로 보내는 내용 
{
  "model": "claude-sonnet",
  "prompt": "다음 문의를 한 줄로 요약해줘: '배송이 3일째 안 와요...'",
  "max_tokens": 100,
  "temperature": 0.3
}

여기서 model은 "어떤 AI 모델을 쓸지", prompt는 "AI에게 실제로 시킬 지시문", max_tokens는 "답변 길이 제한", temperature는 "답변이 얼마나 창의적/일관적일지"를 정하는 값입니다. 기획 단계에서 "이 파라미터 값을 바꾸면 결과가 달라진다"는 정도만 알아도 개발자와 대화하기 훨씬 수월해집니다.

이 요청을 받은 AI 서버는 모델을 실행한 뒤, 아래와 같은 형태로 응답을 돌려줍니다.

응답(Response) 예시 — AI 서버가 우리 서비스로 돌려주는 내용 
{
  "text": "배송 지연 3일째, 고객이 불만을 제기함",
  "usage": {
    "input_tokens": 42,
    "output_tokens": 12
  },
  "status": "success"
}

text가 우리가 실제로 원했던 결과물이고, usage는 토큰 사용량입니다. AI API는 보통 이 토큰 수만큼 요금을 청구하기 때문에, "이 기능을 한 번 실행할 때마다 비용이 얼마나 드는가"를 가늠하려면 이 usage 값을 봐야 합니다. 이 숫자가 바로 월별 AI API 비용 견적을 낼 때 개발자가 기준으로 삼는 값입니다.

정리하면, 우리 서비스는 "무엇을 요약해줘"라는 요청(JSON 형식)을 보내고, AI 서버는 "이렇게 요약했고, 이만큼의 토큰을 썼다"는 응답을 돌려줍니다. 이 왕복 한 번이 바로 "AI API를 호출한다"는 말의 실체입니다.

정리하면

개념한 줄 정의
API서로 다른 시스템이 정해진 형식으로 소통하기 위한 창구
요청/응답내가 먼저 보내는 질문(Request)과 상대가 돌려주는 답(Response)
AI API 요청model(모델)·prompt(지시문)·parameters(옵션 값)를 담아 전송
AI API 응답text(결과물)와 token usage(사용량=비용 기준)를 담아 수신

"API로 연동한다"는 말은 결국 "정해진 형식으로 요청을 보내고, 정해진 형식으로 응답을 받는 구조를 만든다"는 뜻입니다. AI API도 다르지 않습니다. 다만 요청 안에 "AI에게 시킬 일(prompt)"이 들어가고, 응답 안에 "AI가 만든 결과와 그 대가로 쓴 토큰 수"가 들어간다는 점이 다를 뿐입니다.

이해 확인 — 개발자가 "이 화면은 API 응답이 느려서 로딩이 오래 걸려요"라고 말했다면, 이 문장에서 "요청"과 "응답" 중 어느 쪽에 문제가 있다는 뜻인지 스스로 설명해보세요. 다음 모듈(6-2. 노코드/로코드로 AI 자동화 직접 만들어보기)에서는 이 API 호출을 코드 없이 마우스로 연결하는 방법을 다룹니다.

용어 상세

본문에서 밑줄 친 용어를 클릭하면 여기로 이동합니다. 각 항목의 "본문으로" 링크로 원래 위치로 돌아갈 수 있습니다.

API (Application Programming Interface)

↑ 본문으로

서로 다른 소프트웨어 시스템이 내부 구현을 몰라도 정해진 형식으로 요청을 보내고 결과를 받을 수 있게 해주는 소통 창구입니다. "이렇게 요청하면 이런 응답을 주겠다"는 일종의 계약서이자 메뉴판이라고 생각하면 됩니다. 외부 회사의 기능을 우리 서비스에 "연동"한다고 할 때 대부분 이 API를 호출하는 방식을 말합니다.

요청/응답 (Request / Response)

↑ 본문으로

API 통신의 기본 단위입니다. 요청은 내가 상대 시스템에 "이 작업을 해달라"고 보내는 데이터이고, 응답은 상대가 그 작업을 처리한 뒤 돌려주는 결과입니다. 요청에는 주소(엔드포인트), 인증 정보, 실제 처리할 내용(본문)이 담기고, 응답에는 처리 결과와 성공/실패 여부(상태 코드)가 담깁니다.

엔드포인트 (Endpoint)

↑ 본문으로

API 요청을 받아주는 정확한 주소(URL)입니다. 같은 회사의 API라도 "요약해줘"용 주소와 "번역해줘"용 주소가 다를 수 있습니다. 기획서에 "이 기능은 어느 엔드포인트를 호출하는가"가 명시되어 있으면, 개발자와 커뮤니케이션할 때 어떤 기능을 말하는지 훨씬 명확해집니다.

API 키 (API Key)

↑ 본문으로

"이 요청을 보낸 사람(또는 회사)이 이 API를 쓸 자격이 있다"는 것을 증명하는 비밀번호 같은 문자열입니다. 식당의 회원증과 비슷합니다. API 키가 외부에 유출되면 남이 내 계정으로 요청을 보내고 비용을 발생시킬 수 있어, 절대 코드나 문서에 그대로 노출하면 안 되는 값입니다.

JSON

↑ 본문으로

API 요청과 응답에서 가장 흔히 쓰이는 데이터 형식입니다. { "이름": 값 } 형태로 정보를 정리하는 방식으로, 사람이 읽기도 쉽고 프로그램이 처리하기도 쉬워 사실상 API 데이터 형식의 표준처럼 쓰입니다. 기획서에서 API 명세를 볼 때 대부분 이 형식으로 되어 있습니다.

토큰 사용량 (Token Usage)

↑ 본문으로

AI API 응답에 함께 담겨오는, "이번 요청을 처리하는 데 텍스트를 얼마나 잘게 쪼개서(토큰) 얼마나 썼는가"를 나타내는 값입니다. 대부분의 AI API는 이 토큰 수를 기준으로 요금을 청구하기 때문에, 같은 기능이라도 프롬프트를 길게 쓰거나 답변 길이를 늘리면 비용이 올라갑니다. 기능 기획 시 예상 비용을 가늠하는 핵심 지표입니다.
