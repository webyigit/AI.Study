Module 1-3

학습(training)과 추론(inference)의 차이

"모델을 만드는 일"과 "모델을 쓰는 일"은 완전히 다른 단계입니다. 이 둘을 구분하지 못하면 실무에서 "왜 이렇게 느리고 비싸지?" 같은 질문에 답할 수 없습니다.

본문 한눈에 정리 용어 상세 참고문헌

1-2에서 LLM이 토큰을 하나씩 예측하는 과정을 봤습니다. 그런데 "다음 토큰을 얼마나 정확히 예측할지"를 결정하는 능력 자체는 언제, 어떻게 만들어질까요? 이번 모듈에서는 그 능력을 만드는 사전학습 단계와, 만들어진 능력을 실제로 사용하는 추론 단계를 구분합니다.

1) 사전학습(pre-training) — 모델이 "배우는" 단계

사전학습은 아직 아무것도 모르는 모델에게 인터넷 텍스트, 책, 코드 등 방대한 데이터를 보여주면서 "이 문맥 다음에는 이런 토큰이 자주 나오더라"는 패턴을 스스로 찾게 하는 과정입니다. 이 과정에서 모델 내부의 파라미터(수십억~수천억 개의 숫자, 자세한 설명은 1-4 참고)가 조금씩 조정됩니다.

비유 — 사전학습은 신입 직원이 입사 전에 업계 전체의 책과 문서, 회의록을 몇 년치 통째로 읽으며 "이 업계에서는 대체로 이런 식으로 말하고 판단하는구나"를 체화하는 과정과 비슷합니다. 특정 회사의 업무를 배우는 게 아니라, 언어와 지식 전반의 감각을 기르는 단계입니다.

이 단계는 막대한 양의 GPU 연산과 몇 주~몇 달의 시간, 수백억 원 이상의 비용이 들어갑니다. 그래서 사전학습을 처음부터 직접 수행할 수 있는 곳은 OpenAI, Anthropic, Google 같은 소수의 회사뿐이고, 우리 대부분은 이미 사전학습이 끝난 모델을 "가져다 쓰는" 입장입니다.

2) 파인튜닝(fine-tuning) — 배운 모델을 "다듬는" 중간 단계

사전학습을 마친 모델은 언어를 꽤 잘 다루지만, 특정 업무나 말투, 형식에 맞춰져 있지는 않습니다. 이럴 때 이미 사전학습된 모델을 가져와, 상대적으로 적은 양의 전용 데이터로 추가 학습시켜 특정 목적에 맞게 다듬는 과정을 파인튜닝이라고 부릅니다. 사전학습이 "기초 체력을 통째로 기르는 것"이라면, 파인튜닝은 "그 체력을 특정 종목에 맞게 다듬는 것"에 가깝습니다.

파인튜닝은 사전학습과 추론 사이에 있는 중간 단계이자 선택 사항입니다. 모든 모델이 파인튜닝을 거치는 것은 아니며, ChatGPT나 Claude 같은 대화형 모델은 사전학습 이후 사람의 대화 습관에 맞추는 추가 학습(지시 따르기, 사람 피드백 반영 등)을 거칩니다. 파인튜닝을 우리 조직 데이터로 직접 수행하는 방법과 실무 판단 기준은 Phase 6에서 자세히 다룹니다.

3) 추론(inference) — 우리가 "쓸 때" 실제로 일어나는 일

추론은 이미 학습이 끝난(파라미터가 고정된) 모델에 입력을 넣고, 그 입력에 대한 출력을 뽑아내는 과정입니다. 우리가 ChatGPT나 Claude 채팅창에 질문을 입력하고 답을 받는 모든 순간이 바로 추론입니다. 1-2에서 본 "토큰화 → 확률분포 계산 → 토큰 선택 → 반복"의 전체 과정이 바로 추론 단계에서 일어나는 일입니다.

학습이 "역전파(backpropagation)"를 통해 파라미터를 조금씩 고쳐나가는 무거운 계산이라면, 추론은 이미 고정된 파라미터로 입력을 한 번 통과시켜 출력을 뽑는 상대적으로 가벼운 계산입니다. 그래서 학습은 몇 주가 걸리지만, 추론은 우리가 채팅창에서 체감하듯 몇 초 안에 끝납니다.

4) 추론비용 — 실무에서 매번 체감하는 값

추론은 학습에 비해 가볍지만, 공짜는 아닙니다. API를 호출할 때마다 서버의 GPU가 우리가 보낸 토큰을 처리하고 새로운 토큰을 생성하는데, 이 계산에는 그때그때 실제 비용이 듭니다. 그래서 OpenAI, Anthropic 같은 제공사는 "입력 토큰 수"와 "출력 토큰 수"를 기준으로 요금을 매깁니다. 대체로 출력 토큰이 입력 토큰보다 비싼데, 새 토큰 하나를 만들 때마다 그 앞의 모든 문맥을 다시 참고해야 하기 때문입니다.

실무 감각 — 같은 요청이라도 (1) 더 큰 모델을 쓸수록, (2) 프롬프트나 대화 기록이 길어질수록, (3) 응답 길이가 길어질수록 추론 비용과 응답 속도가 함께 늘어납니다. 그래서 실무에서는 간단한 분류·요약 작업에는 가볍고 저렴한 모델을, 복잡한 추론이 필요한 작업에만 크고 비싼 모델을 쓰는 식으로 비용과 속도를 관리합니다.

즉 "이 기능을 LLM으로 만들면 얼마나 들까, 얼마나 빠를까"라는 질문은 결국 추론 단계의 토큰 사용량과 모델 크기에 대한 질문입니다. 기획·운영 관점에서 LLM 기능을 설계할 때 반드시 감안해야 하는 변수입니다.

우리가 실무에서 매일 마주치는 것은 거의 항상 추론입니다. "모델을 학습시킨다"와 "모델을 쓴다"는 완전히 다른 작업이라는 걸 구분하는 순간, API 요금이 왜 토큰 단위로 매겨지는지, 왜 긴 대화일수록 느려지고 비싸지는지가 자연스럽게 설명됩니다.

이해 확인 — "우리 팀이 ChatGPT API로 매달 요금을 내는 건 학습 비용일까요, 추론 비용일까요?"에 스스로 답해보세요. 다음 모듈(1-4. 실무에서 자주 듣는 필수 용어 정리)에서는 이번 모듈에서 다루지 못한 파라미터, 임베딩, 컨텍스트 윈도우, temperature 같은 회의 단골 용어를 한 번에 정리합니다.

용어 상세

사전학습 (Pre-training)

↑ 본문으로

아직 학습되지 않은(파라미터가 무작위인) 모델에게 방대한 텍스트 데이터를 보여주며, 다음 토큰을 예측하는 능력을 처음부터 익히게 하는 학습 단계입니다. 라벨이 붙지 않은 데이터를 그대로 사용하는 비지도 학습 방식이 일반적이며, LLM 개발 과정에서 가장 많은 컴퓨팅 자원(GPU)과 데이터, 시간을 소모합니다. 이 단계를 직접 수행할 수 있는 조직은 전 세계적으로 극소수입니다.

파인튜닝 (Fine-tuning)

↑ 본문으로

이미 사전학습된 모델을 가져와, 상대적으로 적은 양의 목적별 데이터로 추가 학습시켜 특정 작업이나 말투, 형식에 맞게 다듬는 과정입니다. 사전학습과 추론 사이의 중간 단계이며 선택적으로 수행됩니다. 조직 내부 데이터로 직접 파인튜닝을 수행하는 실무 방법은 Phase 6에서 다룹니다.

추론 (Inference)

↑ 본문으로

학습이 끝나 파라미터가 고정된 모델에 새로운 입력을 넣고 출력을 뽑아내는 과정입니다. 우리가 ChatGPT·Claude 같은 서비스를 "사용"할 때 매 순간 일어나는 일이 바로 추론이며, 1-2에서 다룬 토큰화·확률분포 계산·오토리그레시브 생성이 모두 이 단계 안에서 실행됩니다. 학습보다 계산량이 훨씬 가볍지만, 요청마다 실제 비용과 시간이 듭니다.

추론비용 (Inference Cost)

↑ 본문으로

추론 단계에서 요청을 처리할 때마다 실제로 발생하는 컴퓨팅 비용입니다. LLM API는 대개 입력 토큰 수와 출력 토큰 수를 기준으로 요금을 매기며, 모델 크기가 클수록, 문맥(프롬프트·대화 기록)이 길수록, 응답이 길수록 비용과 응답 속도가 함께 늘어납니다. 서비스를 설계할 때 어떤 작업에 어떤 크기의 모델을 쓸지 결정하는 핵심 기준이 됩니다.
